# Agent notes — tommasocostanza.space

Static portfolio site (plain HTML/CSS/JS, no build step) deployed on Vercel.
3D solar-system homepage built with Three.js r128, vendored in
`assets/vendor/` (no CDN dependency — keep it that way; upgrading past r128
would require porting the legacy `examples/js` OrbitControls/GLTFLoader
globals to ES modules).
All site text must be in English (`lang="en"`).

## Architecture

- `index.html` — home: 3D galaxy of category planets, rendered pixelated;
  clicking a planet opens that category's list page (there is no zoom-in
  "system view" with project moons any more — removed July 2026)
- `category.html` — project list for one category, driven by `?cat=<name>`
- `explorations.html` — list page for the "Explorations" category (the Voyager)
- `project.html` — project detail page, driven by `?id=<project-id>`
- `404.html` — space-themed 404 page (floating Voyager)
- `main.js` — all logic for every page (routed via `<body data-page="...">`)
- `projects/projects.json` — single source of truth for projects/categories,
  edited via the custom admin panel at `/admin` (GitHub API, token in localStorage).
  The admin derives each project's id from its name (`slugify`, collision-safe),
  so public URLs stay readable; ids are part of public URLs — do not rename
  ids of already-published projects casually
- `vercel.json` — cleanUrls + rewrites + cache headers

## Routing — deliberately simple

Deep-link routing (`/<category>`, `/<category>/<id>`) was tried and then
REMOVED on purpose (July 2026): the vercel.json `/:category` rewrites never
matched in production and the 404-based fallback added complexity and a
redirect hop. Do not reintroduce it unless the owner explicitly asks.

Current state:
- Project pages: `/project.html?id=<project-id>` only (with `cleanUrls` the
  browser may show `/project?id=...`). `?goto=`/path-based deep links do not
  exist; unknown paths get the custom 404 page.
- Category pages: `/category.html?cat=<category>`; the name is matched
  case-insensitively against `projects.json` and unknown ones go to `/404`.
- Internal navigation: category planets → `/category.html?cat=`, the Voyager →
  `/explorations`, every project card → `/project.html?id=<id>`. A project's
  back link returns to its category page (Explorations ones to the list).
- Readable URLs come from readable project ids, generated by the admin panel
  from the project name (see below) — not from URL rewriting.
- `main.js` init uses `onDocumentReady()` (safe regardless of when the
  script is loaded); keep it.

## The pixelated look

The solar system is deliberately pixel-art. `sizeRenderer()` in `main.js`
renders the WebGL buffer at `1/PIXEL_SIZE` of the canvas's CSS size and CSS
(`image-rendering: pixelated` on `#webgl-canvas`) blows it back up without
smoothing. `PIXEL_SIZE` is the one knob for how chunky it looks.
Consequences to preserve:
- `renderer.setSize(..., false)` — the `false` keeps CSS sizing intact
- `setPixelRatio(1)` and `antialias: false` — smoothing fights the effect
- labels live in `#labels-container`, a separate DOM layer above the canvas,
  so they stay sharp. Do not draw text into the WebGL scene.

## Performance rules

- `assets/Voyager.glb` is ~3 MB. Only `index.html` may preload it.
  `project.html`, `explorations.html` and `404.html` must NOT preload it.
- Homepage Lighthouse baseline is ~90 (measured on `/`).

## Testing

- e2e suite: `npm test` (Playwright vs `python3 -m http.server 8000`,
  config in `playwright.config.js`). Tests are data-driven: journeys pick a
  real project from `projects/projects.json`, so content edits via the admin
  don't break them. The local server has no Vercel rewrites — only test
  behaviors that don't depend on them.
